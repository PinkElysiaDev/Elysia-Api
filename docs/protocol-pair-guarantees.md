# 四协议转换能力与边界

[文档索引](README.md) · [可配置转换](conversion-implementation.md) · [思考与存储意图](protocol-reasoning.md) · [缓存契约](cache-usage-contracts.md)

Chat Completions、Responses、Anthropic 和 Gemini 使用同一语义模型。是否能转发取决于实际请求、双方协议修订、模型能力、资源作用域及最终策略。通过某个组合的样例不代表该组合支持所有字段。

## 同协议与跨协议

| 路径 | 契约 |
| --- | --- |
| 相同线格式、兼容映射、相同资源作用域 | 未修改内容保留原生字段和扩展；显式修改覆盖原文；仍需通过能力和格式检查 |
| 不同协议 | 按具名规则映射双方可表达的内容；无法等价表达时诊断近似或拒绝 |
| 自定义协议 | 按实际编解码模块继承默认规则；完全手写的映射需自行声明和验证，不能只凭 ID 或 family 推断支持 |

默认 `compatible` 允许规则明确声明的有损近似并记录诊断；`strict` 拒绝有损转换。默认请求投影对不可表达的已知缓存提示和合法跟踪元数据记录信息级有损省略；这类成功不保证提示在上游生效。工具 `strict` 的省略仍为警告。非流式已知输出选项的无效果规范化在严格模式也可通过。两种模式都拒绝非法输入、资源越界和无法满足的硬约束。未知字段不会因为兼容模式而自动忽略。

## 主要能力

| 内容 | 转换与限制 |
| --- | --- |
| system / developer | Anthropic、Gemini 目标通过规则上提；改变中段作用域或指令优先级属于有损转换 |
| 工具定义、调用和结果 | 保留调用 ID、参数精度与第二轮关联；Gemini 对象结果转文本、字符串结果包装为对象均有诊断，严格模式拒绝类型变化 |
| 多消息与多个文本块 | 保留有序关联；Responses 使用消息容器和 `parentId`，目标无法表达消息边界时显式投影或拒绝 |
| 思考控制 | 按实际模型解析模式、等级、预算、摘要与输出上限；详见[思考转换](protocol-reasoning.md) |
| 签名与加密思考 | 原生资源受来源约束；跨协议可使用 Elysia 认证续传载体，不把一家供应商的签名当作另一家的原生签名 |
| 客户端输出选择 | Chat `include_usage` 与 Responses `reasoning.encrypted_content` 按输出偏好处理；跨协议未知选择项拒绝 |
| 保存与上下文 | `store` 按来源默认值转换；非空 `previous_response_id` 和截断要求需要对应能力，不能随保存降级一起删除 |
| 引用与概率 | Chat↔Responses 公共 URL 引用、logprobs 有映射；文件引用、Gemini grounding 和非空上下文管理没有通用跨协议映射 |
| 用量 | 内部保留原始观测；目标不能表达的明细由具名规则投影，客户端必填零占位不回写计量 |
| 托管工具、媒体及未知原生扩展 | 需要双方实际声明的映射与能力；没有通用无损承诺，不能清空内容换取成功 |

旧 Chat `role:function` 历史格式不在通用转换保证内。文件、缓存、会话和签名引用不能跨账号或模型随意复用；客户端压缩、合并历史也可能破坏恢复关联。

## Gemini 安全设置

同协议保留 `safetySettings` 的原始形态。跨协议时，null 或空数组可规范化为无分类覆盖；已识别分类全部使用 `BLOCK_NONE` 或 `OFF` 时，兼容模式可移除目标无法表达的设置并记录损失，严格模式拒绝。实际阻断阈值、未知分类或附加属性不能自动删除；非法类型和重复分类直接拒绝。

该规则不关闭目标供应商自身审核。`systemInstruction.role` 是系统指令容器的字段，不会把系统正文降为普通 user，也不会把普通消息提升为系统指令。

## 流式与验证

流必须保持项目身份、开始/结束顺序、内容关联和用量尾帧。已经写出的正文不能被终止快照改写。错误、取消或上游失败不能生成虚假的成功终止；流式开始后不重放生成请求。

四协议的 16 个方向需分别检查 JSON/SSE、单工具与并行同名工具的完整两轮历史。SDK 测试必须消费完整结果并检查隐藏错误，不能只断言出现了正文。真实供应商和用户客户端按[验证方法](protocol-release-readiness.md)单独检查。
