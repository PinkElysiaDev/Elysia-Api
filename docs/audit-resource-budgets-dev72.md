# 大请求资源预算修复与验收记录

> 历史验收记录：下文一次性 `TestLargeRequestResourceProfile` 已在[测试裁剪](backend-test-review.md)中移除；当前功能边界测试和显式大请求入口见[资源预算说明](protocol-resource-budgets.md)。

基线：`22ad012`／dev.71。验证代码：`212d16b`／dev.72。本轮仅使用合成数据、历史测试和本地模拟上游；未推送、未调用收费渠道。

## 修复内容

计数器没有跨检查累加。原始请求和原生快照、消息、工具结果及其解析内容在内部重复表示，过去被套用同一个 8 MiB／100,000 节点正文限额。

现在实际请求使用调用开始时固定的 `maxBodyBytes`，缺省 32 MiB；内部表示使用独立的字节 ×8、节点 ×16、深度 ×4 预算。响应和 SSE 单帧仍为 8 MiB，表达式步数、修改次数、状态项、定义文件、日志和续传存储不随请求正文放大。详见[预算说明](protocol-resource-budgets.md)。

已贯通 typed 与通用映射、逐规则转换、after、原生快照回放和协调、网关、Agent 共用收集器、预览及组合验证。原生快照使用源边界，最终出站请求使用目标边界，允许将大输入缩小后发往有限额的目标。正文、图片、工具关联、未知字段、数字精度和签名保护继续保留。

资源错误保留类型、数量和原始错误链。入站字节超限返回 413，其他本地请求资源超限返回 400／`limit_exceeded`，日志及页面显示发生阶段。响应超限保留响应归属；供应商失败、非成功 HTTP 和取消不会被次级资源错误覆盖。

## 回归范围

- 原错误的独立复现：3 MiB 工具内图片触发旧内部字节上限，1,800 个短文本工具结果块触发旧内部节点上限。修复后完成解码、转换、编码，内容一致。
- 实际本地 HTTP：9 MiB 及专项 31 MiB 图片和工具历史经过 `/v1/messages` → 模拟上游 → 客户端，JSON 和 SSE 均完整消费；每轮上游调用一次。
- 拒绝路径：入站字节、节点及深度超限，零次上游调用；资源错误不会进入生成重试。原生回放、转换规则和 Agent 日志保留正确归属。
- 预算边界：字节／节点／深度恰等于及超过限额；显式限制；较小目标缩小输入；通用模块和 after；大整数和未知字段；循环结构与表达式步数仍受限。
- 配置与跨层：默认 32 MiB，1 KiB 和 64 MiB 配置，Reload 不改变在途预算，溢出配置拒绝发布；9 MiB 管理预览和 Agent 共用收集器成功。
- 页面：资源错误显示为“本地处理失败／资源限制”和转换阶段；既有协议、工具、缓存和取消回归由全量测试覆盖。

## 性能与验收边界

性能测试测量的是完整请求解码、转换和编码的 Go 堆／累计分配，使用合成工具内图片；HTTP 完整链路另外验证。并发 1、4 覆盖 2／8／16／31 MiB，并发 32 覆盖 2 MiB。测试使用 `GOMEMLIMIT=8GiB`（Go GC 软目标），不是进程硬内存限制。采样间隔 20 ms；GC 后的堆存活量不等于操作系统工作集释放量。

最终代码的九组测试均成功，没有 OOM。表中耗时为一组全部工作完成的时间，累计分配量不是同时存活量。测试期间本机还在执行 Go 全量测试，因此耗时不能作为隔离环境下的吞吐承诺。

总体分配量和大正文峰值随输入大小接近线性增长；单次 GC 后仍可能保留运行时缓存，不能宣称空闲进程已回到启动时内存。完整 HTTP 的 31 MiB JSON／SSE 子测试分别耗时 85.65／78.59 秒，每次仅一次模拟上游调用，SSE 收到正常终止。

大请求转换仍有较高的累计分配和耗时。此修复解决错误预算造成的拒绝，没有宣称已经消除内部快照和逐规则 JSON 转换成本；也不把 256 MiB 语义预算宣称为实际进程内存上限。
