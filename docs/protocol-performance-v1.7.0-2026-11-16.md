# 正式 1.7.0 与三分 dev.173 的性能对比

2026-11-16 完成的同机测量表明：dev.173 在八个场景中均有吞吐下降及工作集上升，流式场景差距最大。三分已是实际执行链，但不能据此宣布性能验收通过。

基线为正式 Windows amd64 1.7.0 发布资产，提交 `9b72829a40a6f73cbe82604a6d04e397d8bdf634`，二进制 SHA256 为 `06b878052d2cd9a16f1b7a0be2359257116f6d318945b1fd912645db48644970`。当前为冻结的 dev.173 默认 Spec／Mapping，源码清单摘要为 `110ae220068489d05f89c4d5e8996d329b2727864e5f1b74e667f00a6f205579`。

两侧均使用 Go 1.27.2、CGO=0、GOMAXPROCS=2、GOGC=100、GOMEMLIMIT=2GiB。客户端、网关和固定模拟上游是独立进程；每场景五轮交替顺序，正文日志关闭，测量期间无测试、构建或 profiler。80 个窗口完成 103,680 个测量请求及 1,840 次预热，逐窗口核对输出与上游命中数，所有子进程正常退出。未调用真实供应商。

沿用既有固定种子 bootstrap 的独立中位数比值 95% 区间，八组吞吐与工作集差异均判定为退化。跨协议 JSON 的 CPU 中位数增加 29.2%，但其比值区间为 0.960–1.417，仍属不确定；另外七组 CPU 增加的区间不跨 1。每侧只有五个样本，不代表所有机器和负载，不将全部开销归因于某个单独补丁。

1.7.0 正式资产的构建信息标记 `vcs.modified=true`，因此按发布资产哈希识别，不声称它是纯净源码重建。当前构建关闭 PGO，并使用仓库内 WebUI 占位资源；本次未测 UI、冷启动或配置编译时间。当前 `AppVersion` 字符串仍为 1.7.0，实际身份由 dev.173 编译器、源码摘要及 AppCommit 区分。

发布资产不提供分配字节、分配次数、GC 暂停和采样堆峰值，这些指标未测，不能记为零。工作集峰值按 20 ms 采样；恢复堆是在一秒自然恢复后读取，不等于强制 GC 后的存活量，也不证明内存泄漏。此比较的基线是正式 1.7.0，与[独立 D0 门槛](performance-production-d0.md)不同。
