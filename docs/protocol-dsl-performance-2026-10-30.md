## 后续定位：仍然物化的语义 JSON

在 `0a5d2167` 对应执行代码上，单独运行五次
`BenchmarkReviewRequestBoundaries/json-rule` 分配诊断；它是组件样本，
规则及调用边界与完整 HTTP 不同，约 292 MB/op 不能直接对比上表的完整请求。

profile 显示两个不相交的主要入口是初始 `EncodeSemantic` 和最终
`conversionState.flush` 的 `encodeSemanticWithin`。该采样中前者累计约 481 MiB，
后者约 470 MiB；这些是采样调用链累计分配，不是每请求分配，也不是存活堆。
嵌套 `Value.MarshalJSON`、Compact、编码器扩容以及最终独立字符串占据大头。
父调用与其中 Compact 等子调用的累计值不能相加。

`d8a01ce6` 在保留原有 JSON 同步边界和资源检查的前提下，让已通过检查且编码长度
至少 64 KiB 的 Request 复用已有字段读取器，构造延迟输出计划并只编码最终容器。
小对象和其他类型继续使用现有编码器。选择条件来自原资源计量，不额外遍历一次正文；
非法值和预算错误保留旧诊断路径。最终结果独立持有正文，不保存计划或临时片段。

2 MiB 真实修改的 JSON／SSE 两个场景达到本阶段分配下降 50%、延迟下降 25% 的目标。
五对分配和延迟均向改善方向变化；JSON 延迟配对变化范围为 −51.26%～−31.00%，
SSE 为 −34.36%～−15.86%。工作集峰值配对中位分别下降 45.08% 和 48.49%。
这些是完整请求结果，但仍只属于表中本地合成场景，不能宣称四预置迁移或全部性能验收完成。

1024 帧流的延迟变化为 +0.51%、−3.87%、+3.71%、+7.49%、+8.76%，
有方向及幅度波动。独立五对确认的延迟配对中位为 −0.30%、分配 −0.23%；
延迟五对为 −0.30%、+11.17%、+5.77%、−19.99%、−6.36%，不能据此给出稳定提速或回退结论。
同组小请求确认中位延迟 −0.25%、分配 +1.81%。这些波动结果全部保留，
不通过挑选其中一组宣称所有正常路径已完成性能验收。
对比包含期间所有提交，不能把总体改善全部归因于单个编码提交，
也不能与此前约 9.8% 的改善相加。

两组复测共 70 个批次的请求与上游次数相等，完整消费校验通过；
本组主要矩阵的末次恢复采样活动数和日志队列载荷均为零。
Windows amd64 是本次运行平台。源码核查显示固定 Go 1.27.2／Sonic v1.15.4
在 Windows arm64 仍选择原生 Sonic，但未在该平台运行验收。
其他架构和不同 Go 版本的标准库兼容路径也不能由本组结果代替。
