## 后续定位：仍然物化的语义 JSON

在 `0a5d2167` 对应执行代码上，单独运行五次
`BenchmarkReviewRequestBoundaries/json-rule` 分配诊断；它是组件样本，
规则及调用边界与完整 HTTP 不同，约 292 MB/op 不能直接对比上表的完整请求。

profile 显示两个不相交的主要入口是初始 `EncodeSemantic` 和最终
`conversionState.flush` 的 `encodeSemanticWithin`。该采样中前者累计约 481 MiB，
后者约 470 MiB；这些是采样调用链累计分配，不是每请求分配，也不是存活堆。
嵌套 `Value.MarshalJSON`、Compact、编码器扩容以及最终独立字符串占据大头。
父调用与其中 Compact 等子调用的累计值不能相加。

`d8a01ce6` 在保留原有 JSON 同步边界和资源检查的前提下，让已通过检查且编码长度
至少 64 KiB 的 Request 复用已有字段读取器，构造延迟输出计划并只编码最终容器。
小对象和其他类型继续使用现有编码器。选择条件来自原资源计量，不额外遍历一次正文；
非法值和预算错误保留旧诊断路径。最终结果独立持有正文，不保存计划或临时片段。

  equality 约 3.48%，规范化约 1.26%；大请求的扫描 CPU 尚未单独证明。

下一步先修复读取的所有权边界，再减少重复字段读取。借用优化必须同时验证小根输出、
跨 binding 的小片段不会保留大父体，不能只把 Clone 去掉就算完成。
新增缓存若需要，只能属于一次计划调用，不能改变公开 ReadObject 的独立所有权，
也不能省略重复键、UTF-8、预算、错误顺序或原生来源检查。
