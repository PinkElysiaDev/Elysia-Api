## 必须保持

- 原先成功和拒绝的线格式输入、输出正文与帧顺序、工具关联、usage、调用次数、取消和终态行为。
- 缺失/null/空集合、零值、数值精度、重复键及当前字符串规范化结果。
- 错误码、错误链、路径、阶段、严重度、规则 ID、诊断顺序及保真分类；新版配置与编译身份的变化单独登记。
- 候选独享可变容器，不可变正文共享；目标处理不能污染源请求或其他候选。
- Native 数组身份、资源作用域、认证续传与最终 wire 校验，不因移除 module 而关闭。
- keep-all 当前矩阵：Anthropic 原样渲染、Gemini 默认满足、Chat/Responses 拒绝。开放新目标另案处理。
- 默认→全局→协议对→source 绑定→model 绑定的覆盖顺序；同 ID 完整替换，显式禁用有效。
- `EncodeRequest` 直调中的身份映射和工具结果解析与完整网关投影分别比较，不能只验证 HTTP 后删除重复入口。

第一批将普通、对象和流终检固定到独立 `compiledWireContract`。开发过渡阶段由编译器从已有模块绑定契约，运行校验不再查询执行映射或按模块名跳过。聚焦测试验证模块移除后仍有校验、原错误链和对象快路径保持、请求流状态独立；相关 Wire、Native、Frame、metadata 及 keep-all 回归通过。本批尚未把内置校验规则迁为 JSON，不计为整个阶段 1 完成。

第二批在编译时为可证明等价的 object、array、map、flatmap、if、choose 表达式选择延迟输出计划，随后覆盖 merge、concat、filter。运行时只执行选定计划，不在失败后重跑。根 read/literal 保留原始 JSON 拼写，容器内保持既有规范化、求值顺序、逻辑步骤和资源限制。字段读取增加同步借用入口，默认调用仍独立持有结果。协议及 builtin 包全量测试通过；组件诊断表明嵌套 1 MiB 正文的分配约由 7.43 MB 降至 2.14 MB，但这不作为完整 HTTP 收益。直接构造 typed 核心对象及全部原语覆盖仍在实施。

第三批加入独立 wire Schema 和按声明顺序执行的条件断言。条件读取整帧，断言选择字段；缺失和 null 保持区别，错误原因使用静态说明，保留错误链。校验入口接收本次请求的 context 和有效预算，流终检也传入该上下文；既有模块保持原验证契约。定向验证覆盖字段修改后拒绝、断言首错、精确整数、动态预算与取消。

随后为新 Spec 编译受限 schema 计划：成功路径不把字符串载荷复制进 interface 树，未知子树仍检查数值转换上限，整文仍检查节点、深度和字节预算。失败路径仅用原库构造已有诊断，不接受原库的成功结果来恢复执行。现有 runtimeValueSchema 不变。重复键、非法 UTF-8、精确整数、nullable/enum 和资源错误差分通过。2 MiB 大字符串组件样本由约 2.14 MB/op 降至 600 B/op；该样本非交替整链路测量，仅用于定位，尚不能作为完整网关性能验收。

`CompilePackage` 已提供独立的 v3 编译入口：Spec 负责线格式，Mapping 负责声明式 program 与 effects，不绑定 module，也不转成 v2 文档再编译。文本协议的请求、响应四个方向通过原始 `Execute` 入口完成往返，并真实执行独立输入/输出契约。emit 的字段复制关系在编译期证明，运行时不逐字段重复比较正文；reject 保留静态说明和 effect ID。完整包、编译器版本、实际引用及独立 wire 契约进入身份哈希。

该入口目前只支持已闭合的 emit/reject；aggregate/default/drop、事件运行及任务/会话操作明确拒绝执行，不静默忽略。core2 原始执行和生产 core1 typed 入口仍有边界，现有加载器、四预置与编译器 dev.78 尚未切换。此阶段是可独立检查的编译功能，不是整套迁移完成。后续直接核心读写资格在编译期预先选择，接入另批提交。

直接核心读写已接入现有纯 transform 请求/响应方向。生成器从全部公开核心字段生成访问器，运行时不反射：解码把已完成输出计划直接写入核心对象，编码按已编译路径读取核心字段。只在原语显式要求 JSON 文本或保留 schema 边界时物化；不重跑映射。原始输出 token 预算在写入结构前检查，未知字段、空值和省略不会借结构解码绕过限制。

`1877bce7` 的 strict-load 资源生命周期已做源码核查：较大的 Resource.ID 可以在私有 `conversionState` 中借用当前语义 JSON，但该状态不跨调用保存。generic Request／Response／Event 路径均先 flush 为独立 Value，再由 `decodeContract` 建立返回对象；直接返回对象的 owned Request／Event 路径初始即为 strict，不进入这次新增 writer。转换动作、DiagnosticSink 和 DeliveryState 不保存该临时状态的资源引用。

续传捕获的实际顺序也在转换之前：`server/gateway_response.go` 先捕获源 Response，`server/gateway_stream.go` 先经源事件 collector 捕获 Node，再调用 conversion。`captureContinuationNode` 随即 Seal 为独立密文，持久化保存密文，运行状态只保留 token 和摘要键。当前未发现 strict-load 借用资源经此路径持续保留额外正文，因此未追加无条件 detach 或重复测试；这是引用生命周期核查，不是新增堆保留实测。结论仅限 `conversionState.load`，不能外推到直接返回事件／响应的解码入口。后续若计划权威态取消最终 JSON／合同解码、直接返回 typed 结果，必须重新审验资源 ID 的独立所有权，不能沿用本结论。
