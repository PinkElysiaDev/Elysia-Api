# 项目架构

[文档索引](README.md) · [开发指南](development.md) · [数据库参考](storage-schema.md)

Elysia API 是自部署 AI 网关。Go 后端负责鉴权、路由、协议转换、Agent 和 SQLite 存储；React 前端通过管理 API 配置模型源、模型组、协议及运行策略。

## 模块职责

| 目录 | 职责 |
| --- | --- |
| `backend/protocol` | 协议定义、编译、语义模型、转换规则、验证、事件与任务状态 |
| `backend/protocol/builtin` | 四种内置协议定义与编解码模块 |
| `backend/server` | 应用装配、HTTP 入口与鉴权、管理 API、CLI、Agent 集成和用量结算 |
| `backend/internal/routing` | 路由快照、模型源凭据解析、模型/Key 调度、并发与日配额 |
| `backend/relay` | 协议 HTTP/WebSocket 传输、流式空闲期限、动态请求超时 |
| `backend/internal/outbound` | 共享出站代理、URL 预校验、连接时 IP 校验与连接池 |
| `backend/agent` | 模型调用循环、工具执行、审批、上下文与会话状态 |
| `backend/storage` | SQLite、加密、迁移、协议修订、任务、日志与统计 |
| `backend/config` | 显式配置加载、校验、原子保存与可热更新的运行策略 |
| `backend/internal/dbpath` | 配置与存储共用的数据库路径派生、符号链接/硬链接冲突校验 |
| `backend/internal/atomicfile` | 配置、密钥、缓存与资产共用的原子文件写入 |
| `packages/webui` | React 管理界面 |
| `scripts` | 构建、浏览器测试、协议验证和原生 App 工具 |

### 依赖方向与职责边界

- `main.go` 是进程入口，负责命令行、首次配置创建、信号和退出码。`config` 不持有全局配置指针，也不通过 `init()` 读写配置或退出进程；多个加载结果相互独立。
- `server/bootstrap.go` 装配存储、日志、协议和后台服务；`server/lifecycle.go` 统一管理启动、请求排空、后台任务取消及最终持久化。`Server` 持有应用资源；后台组件接收显式依赖，不持有整个 `Server`。网关、CLI 和 Agent 的宿主适配器仍通过 `Server` 协调应用能力，不将其视为可独立复用的业务组件。
- `server/http.go` 注册路由并提供公共 HTTP 端点；`server/http_auth.go` 集中处理凭据优先级、面板/推理/Agent 作用域与回环限制。Gin 上下文停留在 HTTP 适配层。
- `routing.Repository` 由消费方声明，只要求构建路由所需的四类读取。`storage.Store` 满足该接口；路由组件不打开或关闭数据库，也不写 HTTP 响应。当前边界复用 `config` 的运行时模型类型及 `storage` 的读取 DTO，不重复维护同形模型。
- `config` 与 `storage` 共享 `dbpath` 的路径规则，`config` 与 `relay` 共享 `outbound` 的网络规则。配置不依赖 SQLite 实现或协议转发适配器。
- `protocol` 核心只依赖底层 JSON/SSE 工具；`protocol/builtin` 依赖协议核心；`agent` 通过已有的调用、持久化及工具接口接入宿主。业务层不会被 HTTP、CLI 或 SQLite 细节反向牵引。
- `server/refresh_jobs.go` 拥有源刷新任务的注册、去重、保存后合并重跑、并发上限与完成等待；`source_service.go` 是 HTTP/CLI 共用的源操作入口，`model_refresh.go` 负责发现与存储的应用协调。关停先取消生命周期，再同步任务注册并等待，避免在关闭存储后启动后续刷新。
- `server/health_checker.go` 只负责探测调度与可用性状态转换，通过消费方声明的存储接口和探测回调接入应用；`health_probe.go` 负责协议与网关适配。`usage_retention.go` 显式接收存储、动态策略和资产生命周期锁，与写入及重置共用锁，不通过 `Server` 访问无关状态。

### 状态所有权与失效约束

`routing.Cache` 将组装结果和授权信息作为只读快照发布。一次加载期间的并发请求合并；每次写入成功后失效并递增代际，旧加载不能回填，后续代际不等待旧加载。读取失败返回错误，不复用已失效的授权。调用方不得修改快照内的模型、密钥切片或 map。

`routing.Scheduler` 封装模型组与源级 Key 游标，候选排序保留原列表；删除组/源时同步清理相应游标。`routing.Sources` 为路由和健康探测提供同一份源地址、密钥及模型权限解析，健康探测可解析暂时不可用的模型，路由装配另行过滤可用性。

`routing.Limiter` 封装预留、释放、实际用量与日切。释放幂等；跨午夜保留在途并发计数，只清空日配额；旧日期的预留及结算不影响新日期。删除后重建的模型组不接受旧预留的释放。出站网络策略目前仍是进程级共享策略，启动和热更新统一发布。

### 开发约定

新增逻辑按业务能力及状态所有权放置：协议语义进入 `protocol`，纯路由策略进入 `internal/routing`，传输适配进入 `relay`，事务和 SQL 留在 `storage`，HTTP/CLI 协调留在 `server`。只有存在明确消费边界时才引入接口，避免为每个函数包装一层服务；共用规则只保留一个实现。

底层返回可包装的错误，由入口决定日志与 HTTP 表示；加载和持久化不依赖隐式进程状态。并发组件内部维护锁，测试通过组件行为验证，涉及日期的边界使用可控时钟。`internal/architecture` 的测试约束包依赖、Gin 边界及进程控制归属，随 `go test ./...` 在 CI 中执行；新增包或跨层依赖需同步审查此约束。

架构约束同时覆盖 `server` 的包依赖白名单、禁止直接引入 `database/sql`，以及三个后台组件文件不得引用 `Server` 或 Gin。它不是“全后端已完成组件化”的证明：用量持久化/统计及部分网关宿主协调仍在应用层，出站策略仍为进程级共享。后续拆分以独立状态和实际消费边界为依据，不以文件长度或接口数量作为完成标准。

## 一次推理请求

1. 按入口固定协议修订，校验调用者及模型组权限，解码为有序语义请求。
2. 展开模型源和可用密钥，读取模型绑定及继承的转换策略。
3. 每个候选独立转换请求，检查模型能力、输出约束、组合证据和最终请求格式。目标限制导致当前候选不可执行时，继续检查其他候选。
4. 对可执行候选排序并应用重试预算；实际转发、估算、任务及会话使用同一份准备好的请求。
5. 解码上游响应或事件，经转换规则后编码为客户端格式。上游原始用量用于内部计量，客户端显示投影不改变原始计数。
6. 记录调用结果、协议修订和转换诊断。流式开始后不重放生成请求；晚到错误通过目标事件和 trailer 报告。

语义模型保留内容顺序、工具关联、资源归属，以及缺失、null、零值之间的区别。同协议原生重放保留未知字段；跨协议只能转换已声明且可表达的内容。详细规则见[可配置转换](conversion-implementation.md)和[思考与存储意图](protocol-reasoning.md)。

## 配置与运行状态

`config.json` 保存监听、数据库路径和运行策略；模型源、模型组、令牌、协议、Agent 会话及用量存放于 SQLite。敏感字段使用主密钥加密；恢复数据库时必须使用匹配的密钥。

协议采用草稿、不可变修订和激活指针。编辑器、Agent、CLI、预览与转发共用编译器和验证服务。请求固定自己的修订与绑定，热更新只影响后续请求。内置预置只读并随程序更新；定制需复制为新 ID。

SQLite 使用单连接，写吞吐受其约束。小时级汇总降低统计查询成本；原始日志保留期与汇总保留期不同，因此日志条数和长期统计不必相等。详见[数据库参考](storage-schema.md)。

## Agent、会话与异步任务

Agent 引擎通过 `StreamCaller` 调用模型，通过工具注册表执行操作，不自行解释供应商线格式。服务层提供协议参数、工具权限和会话持久化。远程入口与权限见[远程 Agent](remote-agent-api.md)。

WebSocket 会话固定双端协议和资源归属，使用有界队列、背压、取消与关闭期限；不提供媒体转码或未声明的自动恢复。异步任务先持久化预留，再提交上游；提交结果不确定时不自动重发，结果结算通过事务与 outbox 保持幂等。
