# C24—C27：缓存真实缺口核验

[English](cache-validation-2026-10-04.en.md) · [字段与自定义协议指南](cache-usage-contracts.md) · [证据索引](protocol-release-evidence.json)

本轮补齐了通用缓存创建映射，并获得 Chat、Responses、Anthropic 的线上非零 SSE 读取及 Anthropic 非零创建证据。**没有证明所有缓存条件通过**：Gemini 显式资源接口不可用，Gemini 网关组未得到非零读取字段，Anthropic `1h` 在第 55 分钟已重新创建。后者在直连也发生，不能归因于网关。

## 范围与版本

站点固定 `https://moyuu.cc`。Chat/Responses 使用 `gpt-6.1-sol`，Anthropic 使用 `claude-haiku-4-5`，Gemini 使用 `gemini-3-flash-preview`；每个模型只使用其指定凭据。本轮实际 **71/96 次**上游调用：主实验 51 次、最终版本补验 20 次。原 `256/256` 账本未改动。新增窗口 UTC 2026-10-03 15:59:03 至最后请求完成约 17:07:50，约 69 分钟；四次清理额度保留，未创建任何远程资源，无需清理。

请求串行、固定单一模型源、输出上限请求值 128，无生成重试、轮换或自动换模型。秘密仅经隐藏输入/环境传给子进程，没有写入源码、命令参数、SQLite 或报告。正文为人工测试内容；证据保留在仓库外 `.cache`。生产配置、数据库结构和正文捕获默认值未修改；没有推送、部署或发布。

主实验固定在 `5333765` / `2.0.0-dev.12`，长时间运行中没有替换转换代码。最终补验的 Node 报告创建于 dev.13，但实际 Go 步骤和 `live.json` 均为 **dev.14**，包含补验前的 Agent 修复 `64d9d9b`；以步骤源码摘要为准。TTL 实验没有在 dev.14 重新预热或等待，不能把 dev.12 的时间证据写成 dev.14 实测。

## 已确认的代码缺陷

| 全包 race 触发现有 Agent 完成顺序窗口：流关闭时运行锁尚未释放 | 调整 defer 顺序，先释放本轮资源与运行锁再关闭事件流；确定性用例在清理回调内检查 EOF，修前失败、修后通过 | `64d9d9b` |

测试设施另修正两点：独立检查器先合并原始帧组成，再做 Anthropic 总量归一化；Gemini 下游检查从实际持久化路由账号取得签名作用域。后一个故障原先发生在**检查器**，原始 HTTP 200 和 SQLite 已正确落盘，不是网关丢失响应。人工签名 fixture 与真实原始响应离线回放均通过，随后最终版本 Gemini JSON/SSE 真转发全部通过。

## 缓存意图与用量明细校验（C28—C29）

以下规则由编译器在编码前强制，违反者报错并给出具体路径，不再静默通过。它们与[用量契约](cache-usage-contracts.md)的分桶省略共同构成 C28—C29 的行为变化，编译器版本随之升至 `2.0.0-dev.18`。

- **保留键**：Chat/Responses 目标的 `Details` 不得占用 `input.cached_tokens` 与 `input.cache_write_tokens`——这两个名字归规范化计数器（读取与创建）。映射表达式写入同名 detail 会覆盖由计数器派生的值，使线制输出与语义用量各说各话；现在直接拒绝并指出冲突路径。
- **重复意图**：同一 `Kind` 的多个缓存意图映射到同一线制字段时报错。此前只有 `breakpoint` 分支拒绝重复，`key`/`retention`/`resource` 静默后者覆盖前者，到达上游的请求不再等于调用方描述的请求；现四类一致报错。
- **Anthropic 断点 TTL 顺序（非阻断）**：上游处理顺序为 tools → system → messages，其文档要求较长的 TTL 排在较短之前；未显式设置 `ttl` 的断点按 **5m 默认**参与排序。与其他两条不同，违反该顺序**不报错**：`warnBreakpointOrder` 产一条 `SeverityWarning` 诊断，请求照常编码。上游并未文档化该顺序的失败状态，任何参考实现也都不校验它，因此把布局非最优的请求 4xx 会拒掉本可正常命中缓存的流量——记警告、仍转发，由调用方自行择优。

## 逐项真实结果

| 目标 | 代码与站点可用性 | 观察到的非零计数 | 客户端与 SQLite | 未闭合部分 |
| --- | --- | --- | --- | --- |
| Chat | JSON/SSE 可用；标准创建映射支持缺失/零/非零 | 主实验直连/网关 SSE 读取 4,224；dev.14 任意 ID 网关副本再次读取 4,224 | 成功请求的原始上游、客户端、SQLite 与独立检查一致 | 线上创建均明确零；`24h` 超出本窗口 |
| Responses | JSON/SSE 可用；标准创建映射同上 | dev.12 与 dev.14 直连/网关 SSE 均出现读取 4,224 | 一致 | 线上创建均明确零；`24h` 未验证 |
| Anthropic | 新 Claude 模型符合标准未缓存输入口径；JSON/SSE 可用 | dev.14 冷请求创建 4,633，重复 SSE 读取 4,633；网关冷请求本身也是 SSE | 创建、读取、输入总量和创建分桶均保留 | `1h` 保留正向未成立；旧 GPT wrapper 的计费口径冲突仍独立存在 |
| Gemini | JSON/SSE 可用；支持声明 `cachedContent` 与作用域检查 | dev.14 直连 SSE 输入 9,252 / 18,468 时原生读取 4,079 / 16,351 | 所有已返回的计数均一致；网关组读取字段缺失也保持缺失 | 网关组非零读取未观察到；显式资源创建接口拒绝，引用/到期未执行；无等价生成创建计数 |

Gemini 初始约 4K 的实际输入为 4,645；补验约 8K、16K 的实际输入为 9,252、18,468。以实际 usage 为准，没有把估算文本长度当 token 数。较长直连组证明本次新模型出现过**自动**缓存读取，不能代替显式资源证据。网关两组的原始上游响应没有 `cachedContentTokenCount`，因此不存在“上游已报告非零、网关丢成零”的证据；账户路由和缓存条件仍需站点进一步解释。

主实验包含一次 Anthropic 等待响应头超过 90 秒的超时，结果不确定，没有自动重放。另一项 Gemini 检查器作用域失败已如上修复。主报告保留 `failed` 状态。最终补验 20 个转发用例全部通过，但缺少 Gemini 网关组非零读取，报告保持 `inconclusive`，没有把 HTTP 200 或断言通过改成“所有缓存证据通过”。

## Anthropic 分母及统计

TTL 预热原始字段为 `input_tokens=3`、`cache_creation_input_tokens=4635`、读取 0，因此总输入 **4,638**；5 分钟读取请求为未缓存 3、读取 4,635、创建 0，总输入仍为 4,638。dev.14 新前缀对应未缓存 3、创建或读取 4,633，总输入 **4,636**。这些值在客户端、SQLite 和独立原始帧检查器一致，未出现旧计费扩展口径冲突。

dev.14 各网关组的两次请求累计：

| 目标 | SQLite 总输入 | 总读取 | 聚合命中率 |
| --- | ---: | ---: | ---: |
| Chat | 8,850 | 4,224 | 47.7288% |
| Responses | 8,844 | 4,224 | 47.7612% |
| Anthropic | 9,272 | 4,633 | 49.9676% |

Anthropic 的该聚合包含一次冷创建和一次读取，不能用单次读取请求的约 99.9353% 代替总体比例。独立审计逐条去重实际 SQLite request ID、累计原始组成并核对每个聚合快照，结果无差异。Gemini 聚合读取为 0 是现有统计对未报告读取的汇总结果；逐请求 `CacheRead` 仍缺失，**不能解释为观察到零命中**。未改变统计分母公式或数据库结构。

历史 GPT wrapper 同时给出原始输入 4,421、读取 4,224、计费总输入 4,421；标准公式为 8,645（48.86%），计费口径为 4,421（95.54%）。新 Claude 结果验证标准模型契约，不能替旧 wrapper 确定计费含义。没有为 moyuu 自动生成覆盖标准字段的私有计费映射。

历史 Gemini 同一响应的原生读取为 0、计费扩展却有 4,224 / 8,320 / 16,512，旧报告的“完全零读取”表述已在中英文和索引中纠正为**原生与计费扩展冲突**，不倒改历史原始证据。

## 实际时间实验

四组均在直连和网关使用独立前缀，记录请求开始时间。预热 JSON 与复测 SSE 的完整请求仅 `stream` 改变，缓存前缀与字段相同。

| 声明 TTL / 组 | 实际间隔 | 直连 / 网关读取 | 直连 / 网关创建 | 能得出的结论 |
| --- | --- | ---: | ---: | --- |
| 5m / 保留期 | 约 262 / 258 秒 | 4,635 / 4,635 | 0 / 0 | 观察到有效期内读取 |
| 5m / 独立静默 | 约 420 / 420 秒 | 0 / 0 | 4,635 / 4,635 | 观察到静默后读取消失及重新创建 |
| 1h / 保留期 | 约 3,300 / 3,300 秒 | 0 / 0 | 4,635 / 4,635 | 未证明保留一小时；与目标预期不符，直连同样发生 |
| 1h / 独立静默 | 约 3,900 / 3,900 秒 | 0 / 0 | 4,635 / 4,635 | 观察到重新创建；不能弥补第 55 分钟的正向缺口 |

`1h` 预热及重新创建分桶均为 4,624 个 1h tokens 和 11 个 5m tokens。短桶到期本可只影响那 11 个，但实测读取总数为零，不能忽略该结果。没有固定站点背后的供应商、节点或路由，所以不据此宣称供应商的 1h 契约被证明失效。

TTL 是读取后刷新的**最短**生命周期，超过 TTL 仍命中不构成失败。本轮没有“读后再等待到原到期点之后”的刷新对照，因此没有独立证明刷新延长寿命。主实验旧 `timing` 标签只表示计划观察完成；新增分类明确区分到最短期之前无读取、期后重新创建、期后仍读取与无法判断，避免把完成请求当成 TTL 通过。

Gemini `POST /v1beta/cachedContents` 实际返回 HTTP 404 和 `Invalid URL (POST /v1beta/cachedContents)`，在第一资源创建处停止。没有可供查询/引用的资源身份，故资源 `expireTime` 对照及清理均未执行；未将隐式缓存命中替代此项。

## 性能复核

基线为 `fc31fea` / dev.11，候选为 `64d9d9b` / dev.14，同机 Ryzen 5 7600X、Go 1.26.5、Windows amd64。线上请求与其他验证结束后串行测量，无剖析，每项十组、每组 300ms，覆盖缓存转换、64 KiB 流解码、四路径 × 四请求内容，以及旧创建别名的解码—修改—编码，共 19 项。

首轮有 13 项 CPU 指标的 95% 比值区间下界超过 1.05，没有忽略这些结果。随后对**全部 19 项**按候选—基线—基线—候选复验，每阶段五组，仍为各版本每项十组独立样本。比较使用固定种子 `20261003`、10,000 次 bootstrap 中位数比值区间。结果如下：

| 场景 | 基线 → dev.14 中位数 | CPU 比值 / 95% 区间 | 分配字节 |
| --- | --- | --- | --- |
| 缓存请求转换 | 55.791 → 58.635 µs | 1.051 / 0.990–1.092 | 36,409 → 36,408.5 B |
| 64 KiB 流解码 | 2.262 → 2.345 ms | 1.037 / 0.982–1.086 | 2,077,174 → 2,081,269.5 B |
| Chat → Responses 256 KiB | 10.258 → 10.429 ms | 1.017 / 1.001–1.071 | 8,042,600 → 8,040,330.5 B |
| 旧缓存别名语义修改 | 91.767 → 104.954 µs | **1.144 / 1.088–1.211** | **66,020 → 77,878 B** |

前 18 项没有复现有统计支持的超过 5% 回退，也不能据此证明严格的 5% 非劣性。第 19 项重复确认 **+14.4% CPU、+13.187 µs、+11,858 B（约 18.0%）、+208 allocations（1,101 → 1,309）**。它专门覆盖旧原生别名经过语义修改的响应，不代表普通请求转换全部增加这个比例；本轮没有重跑 HTTP 压力矩阵，不能从微基准推断生产吞吐。

修复增加了标准嵌套字段和原生别名协调，避免旧计数残留，因而保留该正确性修复并公开开销。单独三秒剖析中，`encodeResponseUsage` 的累计 CPU 约 7.82%、累计分配约 10.32%；原生协调累计约 22.53% CPU / 44.61% 分配。累计比例有调用包含关系，不能相加，也不是预计可消除的成本。带剖析的时间未用于基准比较。

后续定向优化方案：在**一次响应编码调用内**只解析一次兼容原生 usage 的字段存在性及已知别名，将只读结果共享给修改前/后的构造；减少完整对象拆解和重复中间编码。保留同源检查、缺失/零、别名冲突、删除及未知扩展规则，不建立跨请求缓存，也不让借用的 JSON 视图进入长期状态。先用现有修改/删除与差分样例证明等价，再进行各版本至少十组交换顺序采样、代表性 HTTP 负载和全包 race；只有收益稳定且无新的退化才合入。该优化尚未实现，不以未经验证的重构替代本轮实测。

证据为 `c27-performance-baseline`、`c27-performance-candidate`、`c27-performance-comparison.json` 与 `c27-performance-followup`。初筛与复验均保留。**别名修改成本仍是已知性能回退，本轮不宣称所有性能发布门槛通过。**
