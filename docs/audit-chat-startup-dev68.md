# Chat 流启动身份兼容验收（dev.68）

本次修复已在真实渠道捕获到异常启动组合，并完成四种客户端协议和七种流式 SDK 组合的消费验证。完整审计仍包含直连身份变化、Responses 扩展事件及一项随后修正的取消断言失败，不能据此宣布所有渠道场景通过。实际 VS Code／Claude Code 界面本轮未复测。

## 实现与边界

- 基线：`0037a4e`；实现提交：`a811c6f`、`47d48cb`。编译器从 `2.0.0-dev.67` 升为 `2.0.0-dev.68`，沿用既有证据重验机制。
- 新阶段 `source_event` 只允许专用动作 `chat_stream_identity`，规则 ID 为 `chat-stream-identity`。通用字段修改动作没有获得解码前执行权限。
- 按实际安装的 Chat 事件解码器和四种内置事件编码器启用默认规则，包含同协议及复用模块的自定义协议；手写映射不按名称或 family 匹配。
- 每次上游响应独享状态，最多暂存首条空 assistant 启动帧。第二帧满足完整字段边界、模型相同且 ID 不同时，只修正首帧的 `/id` 和发生变化的 `/created`，随后按原序处理两帧。使用精确 JSON 值，不经浮点重建。
- 首帧必须包含空字符串正文；第二帧正文只允许缺失或空字符串。两个 choice 均须唯一、index 为 0、角色为 assistant。允许的 null 元数据及第二帧 service tier 均不移动、不覆盖。工具、思考、正文、非空 usage、额外字段不触发此规则。
- 正常流原始载荷不改写。仅时间变化、正文后的身份变化、第三种 ID、模型变化、非法时间及多 choice 继续接受原校验。
- 严格模式拒绝必要的修正，禁用规则恢复原校验行为。每个修改字段记录 `lossy_compatible` 诊断，包含来源协议、`decode_event`、`conversion.source_event`、帧序号、规则来源及策略哈希。
- 原始帧先记录，修正后才建立解码器和原生快照身份。没有整流缓冲、时间容差或生成重试；EOF 交回生命周期校验，取消和读取失败释放暂存。
- 网关、预览及组合验证共用状态处理；独立编解码器验证继续要求标准流。预览使用 `sequence:true` 帧数组。最终用户映射后的身份检查保持有效。

接入组合回归时发现，响应级 fingerprint 与 choice 级 logprobs 同时出现会受扩展 map 遍历顺序影响。已对扩展所属路径排序并增加回归，消除证据比较的随机顺序差异，没有放宽字段归属检查。

验收末尾另补充了 JSON 转义字符串边界：`object` 和 `role` 比较解码后的字符串，允许合法的 Unicode 转义拼写；除要修正的身份字段外，其余字段的原始 JSON 值保留。该小修发生在两次仓库全量测试启动之后，另外执行协议包全量、相关网关、vet 和 race 验证；真实渠道本轮捕获的普通字符串形态不受此调整影响。

### 取消断言复核

取消现在须先读到完整 SSE 帧中的有效生成正文，同一网络分块内若随后出现错误则先报错；空启动帧和已经完成的流不能算取消成功。随后检查持久调用记录，恢复调用独立记结果。

完整审计的 `errors/responses-2/cancel` 记录了 `client_canceled`／499，但编码器因上下文取消产生的 `invalid_input`／`runtime`／`context canceled` 被新断言误当作先前协议失败。原报告保留该失败，不改写为通过。

已修正断言：以 `client_canceled`／499 确认客户端取消，不再按报错中是否含 cancel 判断。只有诊断属于事件编解码运行时、错误码和原因完全匹配取消时才豁免；任何供应商失败、其他错误或混合身份错误仍拒绝。自测覆盖伪装取消和混合错误。随后在同一真实 Responses 渠道独立执行取消及恢复，**2/2 通过**，逻辑状态分别为 499、200；四种协议已有的真实取消记录也通过最终断言回放。专项报告：`scripts/protocol-audit/results/dev68-cancel-followup/report.json`。

- **两项 Chat 直连流失败**：工具、历史场景仍返回启动 ID／时间变化。直连审计不经过网关兼容，继续按标准契约报错；对应 Chat 上游网关场景通过。
