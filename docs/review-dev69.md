额外补查和修复：

- Responses 的 `function_call_arguments.done` / `custom_tool_call_input.done` 引用普通消息项目时，原路径会解引用空 `Input` 并 panic。现先检查项目类型，返回具体 `/item_id` 诊断。`responses_tool_lifecycle_test.go` 先复现 panic，再验证拒绝。
- CLI 删除 Key 的读取错误不再被吞成“不存在”；取消读取回归验证错误原因与原记录保留。
- Agent 修改测试目标先持久化、再发布内存状态；注入写失败后，旧 URL 和凭据均保留。
- 损坏的 Token 授权 JSON 曾被当作空列表，可能扩大访问范围。现读取及相关变更明确失败；合法的旧空列、null、空数组仍兼容。测试覆盖缓存拒绝装载、Token 变更回滚、模型组改名回滚。
- 含引号、反斜杠和 HTML 转义字符的合成秘密，曾在 CLI JSON 渲染后绕过按原值脱敏。新增真实 CLI 入口回归先失败再通过。
- 浏览器中，轮内 `plan_updated` 触发的慢刷新曾覆盖后续 SSE 消息。新增浏览器复现先失败再通过；不能只防轮询开始于流之前的情况。
- Agent 的改名、设置、清空、删除、创建、草稿还原与方案确认回调增加会话选择代次保护；离开再返回同一会话也会使旧操作的页面发布失效。五项延迟 mutation 浏览器回归通过，其中清空、删除和创建已验证修复前覆盖新会话的失败。成功持久化的旧会话变更仍保留，重新进入会话会刷新详情。
- 旧协议 `config:null` 曾在 ID 对账时写入 nil map 并 panic。现按非法定义报告，原始行保留；存储入口回归先复现 panic，再通过。
- 预置改名复制验证报告时沿用全局主键，`INSERT OR IGNORE` 跳过复制，随后删除旧报告。现仅在目标修订存在后迁移报告外键，保留报告 ID、原文、大整数、旧编译器和验证时间。回归覆盖新旧预置共存、两次重放、注入写入失败后的整笔回滚。
- Agent 方案暂停、提问暂停、方案确认、审批补充测试目标及清除已消费审批的写库错误不再被吞掉。五类故障注入均先复现错误续跑或残留 running，再验证失败停止、恢复 idle、保留旧设置、工具不重做且模型不继续调用。
