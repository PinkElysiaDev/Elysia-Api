# 请求资源预算（dev.72）

`maxBodyBytes` 同时约束读取入站正文和最终出站请求，缺省为 32 MiB。配置文件 Reload 只影响新调用；已经开始的调用继续使用开始时固定的限额。此设置独立于 `usageLog.bodyMaxBytes` 等日志保存限额。

| 边界 | 默认字节 | 默认节点 | 默认深度 |
| --- | ---: | ---: | ---: |
| 入站和最终出站请求 | 32 MiB | 100,000 | 64 |
| 上游 JSON 响应／SSE 单帧 | 8 MiB | 100,000 | 64 |
| 请求语义工作表示 | 256 MiB | 1,600,000 | 256 |

语义预算从对应正文预算派生：字节乘 8、节点乘 16、深度乘 4。它包括原始快照、消息和内容块快照以及解析后的工具内容，不等于进程内存上限。正文中的重复消息仍分别计量；图片、签名、未知字段和原生来源不会为了通过检查被删除。

显式协议和策略限额继续收紧相应边界。原生回放检查源快照，最终输出检查目标限额，因此可以将合法大输入映射为更小的请求。表达式步数、修改次数、流状态项、协议定义、日志和续传存储保留独立限制。所有预算乘法在配置或编译时检查溢出。

typed 编解码、通用映射、逐规则转换、after 映射和原生协调共用预算选择。网关、Agent、预览和组合验证沿用同一执行上下文。预览的外层包络单独受限，其中的测试正文仍接受相应边界检查；包络容量不能扩大协议定义文件上限。

实际入站字节超限返回 413；请求节点、深度和语义工作预算超限返回 400，调用记录标记 `limit_exceeded`。诊断记录资源域、数量、阶段及可用的规则／策略身份，不记录正文内容。响应资源超限保留响应阶段归属，已有 HTTP／供应商失败和取消保持主因。资源限制不会触发新的生成重试。

页面将请求转换阶段的资源错误显示为“本地处理失败／资源限制”，并展示发生阶段。不能把此类错误解释为模型供应商失败。

## 本地验证入口

`large_request_test.go` 使用合成图片和工具历史复现原来的字节、节点误拒，并检查原生内容保真、较小目标预算和通用映射。`gateway_large_request_test.go` 通过真实本地 HTTP 网关调用模拟上游，完整消费 JSON／SSE，并检查调用次数、预览、Agent 共用收集器及发送前拒绝。

常规回归用小型可配置缓冲区验证跨越预算边界的行为，避免为同一断言反复传输大载荷。设置 `ELYSIA_RESOURCE_PROFILE=1` 可让 `TestGatewayLargeAnthropicRequest` 使用 31 MiB 图片；分配和吞吐测量使用 `BenchmarkRequestMemoryPipeline` 等基准。旧的一次性 `TestLargeRequestResourceProfile` 已移除，历史测量数据仍保存在对应审计报告中。

真实渠道和原用户长对话的实际客户端复测另行记录。本地合成夹具成功不替代这些验收。
