## 交付范围

四种预置、自定义入口和上游、编辑器、Agent、预览与验证统一使用 `backend/protocol`。旧转换执行内核已经移除。新协议在当前引擎可表达的语义与传输范围内，通过声明方向、能力、映射、操作和样例接入，不要求修改 Go。无法表达的能力产生诊断，不能以静默删除换取成功。

HTTP JSON、SSE、NDJSON、声明式 WebSocket 会话、持久化异步任务均有本地集成证据。编辑器和 Agent 使用相同的版本、验证和启用服务；保存草稿不启用，旧报告不证明新内容。Agent 不执行客户端业务工具。

这不是“所有 API 的所有新机制已经兼容”的声明。协议两端必须能等价表达所需能力；模型输出、供应商策略、缓存资源与签名的跨账号复用不属于转换保证。

## 性能结论

同一台 Ryzen 5 7600X 上，Chat 缓存请求转 Anthropic 的 C01 基线为 29.2–30.8 µs / 18.0 KB / 322 次分配；C17 为 90.8–96.3 µs / 53.8 KB / 752 次分配。已通过剖析移除重复 JSON 序列化、容器解码和限制扫描开销，但请求 CPU 仍约为旧边界的 3 倍，不能报告为无回退。

64 KiB 流解码由历史 3.58–4.56 ms / 9.98 MB 降为 3.04–3.34 ms / 2.41 MB。新的请求边界还执行来源、原生保留、能力及资源约束；没有为满足旧基准而删除这些检查。部署吞吐与延迟目标仍须在目标硬件和并发下测量。

## 构建与主机验证

```sh
node scripts/build-standalone.mjs
node scripts/smoke-standalone.mjs
```

冒烟脚本创建新的临时目录、数据库、随机管理令牌和本地端口，禁止模型目录网络同步。检查 `/health` 的数据库、提交标识，管理 schema 的编译器版本，四个活动预置，以及嵌入 UI 和 JS 资源。只关闭它自己创建的进程。输出目录保留 `evidence.json`、服务日志和数据库；证据包含二进制 SHA-256，不打印令牌。其他平台没有实际运行证据。

提交后重新构建，使 `/health.commit` 对应 C18；产物不入 Git。报告本身不写自身提交哈希，避免为更新哈希不断产生新提交。可用以下命令查验本地提交与产物：

```sh
git log --oneline --reverse 8a0b23f..HEAD
git log -1 --format='%h %s'
```

## 升级与回滚

1. 保留旧可执行文件，以及同一时间点的配置、数据库和匹配主密钥。停止旧程序后复制，或使用一致的 SQLite 备份；不能只复制仍在写入的主数据库文件而忽略 WAL。
2. 在副本上运行迁移预演，处理编辑过的预置、自定义定义和绑定诊断。全部验证通过后，按相同意图执行事务迁移；服务端重新验证，失败保持可修复管理状态。
3. 未修改预置按已知完整内容指纹升级；用户修改不覆盖。记录备份位置和新旧二进制身份。
4. 协议修订回滚使用当前引擎验证过的旧修订。程序/数据库回滚则先停止新程序，恢复旧程序、数据库、配置及主密钥的匹配集合，并核对健康和协议绑定。恢复旧库会丢失备份之后的新记录，先保留当前库以便审计。

数据库迁移不能靠一次 `git revert` 撤销。详见[迁移机制](protocol-migration-v2.md)和[统一切换契约](protocol-cutover-v2.md)。

## 尚未满足的发布条件

需要取得受支持环境下的实际 race 通过结果，并完成拟发布供应商/模型/账号组合的真实请求、流式和工具生命周期验证。线上缓存测试必须固定账号和模型，使用足够长的稳定前缀，在 TTL 内重复请求，并核对读取/创建及总输入计数。

性能成本和跨平台实际运行边界已公开。现有本地证据支持所列工程行为，不等于所有发布门槛已经满足。
