# Gemini 流式工具参数合同

Gemini 的 Spec 允许 `functionCall.args` 缺省。自身 Mapping 的 `decode-stream-tool-part` 按调用 ID 关联更新，再将工具调用转换为大自在天 core2；其他协议的 Mapping 只读取核心工具语义。

参数更新规则如下：

| 输入 | 核心参数 |
| --- | --- |
| 显式 `args` | 使用本帧的对象，保持原始数值精度 |
| 已有关联调用，本帧省略 `args` | 保留该调用之前的参数 |
| 首次调用省略 `args` | 使用空对象 |

省略不等于显式空对象。若已有参数已经转发，后续显式 `{}` 替换非空参数仍由核心的快照一致性检查拒绝；同一调用 ID 改变函数名称也继续拒绝。无 ID 的新调用沿既有身份分配规则处理，不凭函数名称猜测关联关系。

签名仍关联原调用和 provider/account/model scope，不能补造签名或跨 scope 复用。本次修复保持签名资源、来源所有权及去 Native 后的目标重建。测试用 `9007199254740993` 验证参数不经过浮点转换。

dev.173 修复的是 Mapping 将“已有调用省略参数”误写为空对象的问题，DSL、Spec 和核心快照守卫均无需修改。该边界已在当前代码本地复现；它与审验报告 F03 的历史第二轮 400 有关，但尚无证据证明二者根因相同。
