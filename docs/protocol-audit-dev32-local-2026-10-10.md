本轮从 `6f4db1c` 开始，协议编译器提升为 `2.0.0-dev.32`。按用户最新要求，真实 API 测试继续暂停；没有读取或修改 `scripts/protocol-audit/config.local.json`。下述结果来自合成上游、实际本地网关、固定版本 SDK 和隔离数据库，不表示原渠道故障已关闭。

## 根因及修改

此前的最终检查验证了单帧格式和公共语义事件，却没有覆盖若干客户端线格式独有的跨帧约束。语义解码可以根据文本建立回答，因此完全缺失 Chat `assistant` 角色的原生流也会被当作成功；实际 OpenAI SDK 在汇总成功结果时拒绝该流。类似缺口还包括响应身份变化、缺少或重复开始事件、事件类型与状态不一致。最初 17 个负向用例均复现了错误放行，随后补充 Anthropic 未关闭内容块及显式非法角色回归。

共享最终流检查现在在请求独立的目标模块实例中维护受限状态，位置仍在用户 `after`、线格式规则及续传载体处理之后。网关、预览和组合验证调用同一检查：

- Chat：显式角色只能为 `assistant`；成功结束前至少出现一次该角色；同轮 ID、模型和创建时间稳定；结束后只接受不含 choice 的用量尾帧。允许角色晚到或重复，拒绝同帧重复 choice 索引。
- Responses：响应事件之前必须存在且仅存在一次 `response.created`；身份字段稳定，事件类型与状态一致；开始状态允许 `queued` 或 `in_progress`。
- Anthropic：开始事件唯一且先于内容；内容块必须先开始、再增量、再关闭；消息结束增量之前必须关闭内容块；结束之后不能继续输出内容。
- Gemini：可选身份字段仍可省略，出现后保持一致；显式输出角色必须为 `model`；拒绝同帧重复候选索引。

错误事件不要求先产生正常开始事件或 assistant 角色。合法原生帧保留原文，JSON 字符串转义按解码值比较身份。显式非法 Chat/Gemini 源角色在解码时拒绝，避免跨协议重建时悄悄改为合法角色。没有显式角色的源流仍可供其他目标重建完整格式；原生 Chat 成功路径不能借此跳过最终角色要求。本轮不宣称实现多候选流或所有上游契约。

实际 HTTP 回归覆盖缺少角色、ID 改变、模型改变、时间改变：原生首帧不被改写，非法成功终止帧不发出，客户端收到一次包含字段路径的错误及 trailer，持久调用记录标记失败。即使配置最大重试数为 3，上游也只调用一次。自定义模块的 `after` 生成非法帧时，预览和组合验证同样拒绝。

## 旧样例与测试修正

Chat 预置从 `2.2.5` 提升为 `2.2.6`，为三个内置流解码正向样例的首个 delta 补上 `role:"assistant"`，原语义预期不变。旧自定义定义中的这些样例仅在输入与预期的联合指纹精确匹配时修正，经验证创建新不可变修订；原修订和操作员草稿保留。任意用户样例、负向用例和手写／带 `after` 的解码器不自动改写。实际服务刷新测试覆盖旧修订升级、证据生成及十次重复刷新稳定。

第一次 Go 全量测试发现服务器正向夹具也存在相同缺陷：共享缓存 Chat 流、复合帧、取消和纯工具流缺少角色，两个 Responses 工具场景缺少开始事件。修正只补合法字段、开始事件及相应序号；缓存、用量落库、工具关联、取消状态和失败断言不变，没有放宽验证器或批量翻转断言。修正作为独立提交，随后重跑全量测试。
