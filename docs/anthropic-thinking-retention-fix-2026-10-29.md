# Anthropic → Gemini 保留思考设置修复

基线：`9b72829a`，编译器 `2.0.0-dev.77`。修复：`b0c5b01e`，编译器 `2.0.0-dev.78`。当前分支为 `fix/a2a-registration-order-2026-10-26`，仅本地提交，未推送。

## 行为与实现

Anthropic 客户端发送 `context_management.edits:[{type:"clear_thinking_20251015",keep:"all"}]` 时，旧版将整个控制作为未知原生扩展保留，在 Gemini 编码阶段拒绝。新增合成回归在基线复现了相同的 `/wire:claude/context_management/edits` 错误；没有使用私人正文或真实供应商。

现有 `request_projection` 现在将这项控制映射为 Gemini 不清理已提供历史的默认行为。仅在实际源模块为 Anthropic、目标模块为 Gemini 时执行，要求 `context_management` 只有 `edits`，数组恰好一项，编辑只有 `type` 和 `keep`。支持字符串 `"all"` 和 SDK 定义的 `{"type":"all"}`，按 JSON 字符串语义比较。其他结构保持原值，由既有编码器保护处理。

兼容和严格模式都记录一条 `conversion_normalized / info / preserved`，附带原生字段路径、规则、策略和修订。只移除这项控制；其他原生扩展继续保留并检查。Anthropic 同协议、Chat/Responses 目标、规则禁用、未知来源均不由本修复放宽。目标模型的思考能力、供应商签名和加密历史仍独立处理；严格模式仍可能因其他实际损失拒绝整次请求。

生产执行代码增加一个私有方法及调用条件，共 40 行，另更新规则说明与编译器版本。复用不可变值读取器、候选所有权和现有规范化诊断，没有新增 after、通用转换框架、缓存、正文遍历或回退路径。没有公开 API、数据库或用户协议定义迁移；编译器升级沿用现有证据重验。

## 性能对照

同一 Windows amd64 / Ryzen 5 7600X，Go 1.27.2，`GOMAXPROCS=4`、`GOGC=100`、`GOMEMLIMIT=2GiB`，CGO/PGO 关闭。相同基准源码分别链接修改前后生产代码，五对 A/B、B/A 交替运行，每项每次 1 秒。基准期间没有同时构建、运行其他工程检查、启用 profiler 或主动 GC。

以下测量的是**不带新增控制字段的正常成功请求**，防止把旧版拒绝请求的耗时当作修复后成功路径的基线。耗时为五次中位数，变化为两中位数之比。

| 场景 | 原耗时 ns/op | 新耗时 ns/op | 变化 | B/op 前→后 | allocs/op 前→后 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Anthropic → Gemini，短文本 | 73,451 | 73,075 | −0.51% | 23,180 → 23,124 | 482 → 482 |
| Anthropic → Gemini，单条 2 MiB 文本 | 6,532,563 | 6,434,649 | −1.50% | 24,559,917 → 24,553,410 | 535 → 535 |
| Chat 同协议 | 76,570 | 76,661 | +0.12% | 23,873 → 23,943 | 512 → 512 |
| Responses 同协议 | 53,890 | 54,624 | +1.36% | 20,692 → 20,760 | 441 → 441 |
| Anthropic 同协议 | 85,102 | 85,666 | +0.66% | 29,209 → 29,525 | 567 → 567 |
| Gemini 同协议 | 95,608 | 94,881 | −0.76% | 26,733 → 26,626 | 574 → 574 |

全部单对耗时变化在 −5.41%～+4.65% 内；分配量中位数变化在 −0.40%～+1.09% 内，分配次数中位数不变。没有达到 10% 回退复核门槛，不把这些小幅波动宣称为性能提升。

这是完整请求编解码/转换的组件基准，不是完整 HTTP 延迟或采样堆峰值。新增控制实际命中时的诊断和小对象解析仍有成本，本轮未单独量化该增量；没有据此承诺零开销、进程内存下降或所有负载无回退。
