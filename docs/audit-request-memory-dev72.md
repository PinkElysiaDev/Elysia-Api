# 请求全链路内存优化验收记录（dev.72）

> 历史验收记录：冻结内存快照对照及一次性 phase/resource profile 已在[测试裁剪](backend-test-review.md)中移除。下文命令及结果对应原提交；当前请求 pipeline benchmark 仍保留。

基线 8bc0cea，运行时代码 a8341c2，最终测试代码 9b7b526，编译器 2.0.0-dev.72。后续只提交文档和机器可读测量结果，不更改已测运行时代码。本地提交，不推送，不调用收费供应商。

## 改动与保护边界

- typed 请求入口只放行纯内置模块的线格式 schema；输入 schema、输出 schema、能力、资源、来源以及取消检查仍在原边界执行。语义 schema、after、initial 维持通用路径。保留旧 JSON 边界的规范化和错误包装。
- 请求解码的大片段在单次调用中共享不可变 string。最小共享片段为 max(64 KiB, 根正文长度 / 4)。小字段立即分离；资源标识和缓存标识额外独立化，避免长生命周期的小字段拖住整个正文。公开 Bytes 和 ReadObject 的复制契约不变。
- 已验证 Object / []Value 的编码按原键序、转义和数字拼写一次分配输出；任意 Go 对象仍使用原编码器。资源计量按逻辑出现次数累加，没有去重消息、删除快照或降低预算。
- 请求工作区最多保留一个解析基线，记录于授权回调之前；回放继续重做来源、能力、作用域和最终线格式检查。必须为同一固定编译实例，快照、修订、上下文和预算匹配；通用 JSON 边界丢弃工作区。
- 仅首个可用候选保留一次编码结果；禁用缓存合成且符合模块边界时才可消费。模型、正文、上下文、scope 和预算变化时失效。预检诊断在实际发送时发布；所有候选仍做资格预检。
- 日志合法 JSON 一次解析，顺序为轮次状态及普通脱敏、媒体外置、编码、截断；非法 JSON、SSE、嵌套字符串继续原兜底。截断结果和短 MIME 元信息拥有独立存储。
- 日志媒体私有不可变，队列只复制元信息；物化后的流记录释放原始帧。队列同时受 1024 条和 128 MiB 载荷限制，包含后台正在持久化的记录；超额同步落库，失败、reset、关闭均释放登记。128 MiB 不是全进程内存上限。

## 差分证据

- 100 个请求观察与旧版本逐字节比较：语义 JSON、转换结果、输出正文、失败诊断与错误链。该夹具未额外收集成功调用的警告；警告时机与内容由已有协议回归及候选诊断测试检查，不能说这 100 个观察单独证明了所有成功警告等价。
- 四协议 wire / semantic / after / 输入拒绝 / 输出拒绝差分。
- 请求工作区授权回调修改、并发候选、独立编译实例、源上下文和快照失效测试。
- 容器编码数字、转义、空值、nil、重复键、非法 UTF-8 和错误类型；公开复制与短字段所有权测试。
- 80 个日志观察与旧版本精确比较；队列恰好预算、超额、在途持久化、失败、reset、关闭、媒体共享隔离测试。
- 取消与最终格式保护由现有测试及新增模块边界取消测试验证。不能将小输入取消测试当作大请求取消后的内存测量。

## 测量方法

同机器、Go 1.26.5、GOGC=100、GOMEMLIMIT=8GiB，五组交替配对。HTTP 客户端、网关、模拟上游为独立进程，JSON/SSE 完整消费，核对上游调用次数。31 MiB 指 base64 文本，网关内存不包含客户端或供应商堆。采样间隔 20 ms，报告所有峰值以及中位数；它不是连续精确峰值。进程工作集不等于堆。

HTTP 耗时到客户端完整读完为止；累计分配和采样峰值延长至异步日志队列排空。每组 JSON 后 SSE 共享网关进程；两次之间回收堆，工作集可能保留先前映射页面。正式计时没有手动 GC / profile，回收测量另行触发 GC。

31 MiB 四并发门槛：可用承诺额度 >= 16 GiB 且可用物理内存 >= 12 GiB；不够记环境阻塞，不调低并发替代，不修改页面文件。其余工作负载还有保守内存预检，每次记录实际条件。

## 仍存在的成本与适用范围

- 传入 []byte 到 Value 的首次复制、规范化媒体 payload、最终 HTTP []byte 仍然存在。
- 原生协调仍需编码基线和最终输出；消除的是重复解码与多级副本，没有取消未知字段保护。
- 多候选仍逐个做资格检查和编码预检，因此 16 候选 CPU / 分配开销不会接近 1 候选。
- 日志保存正文仍须构造可修改树；媒体外置仍需 base64 解码和哈希。队列预算只约束异步保留，不约束活跃请求和同步写入总占用。
- 带 after / 语义 schema / 非纯模块、缓存合成等不适用优化的路径继续旧行为，收益不能外推。
- 默认 ReadObject 与普通 Go JSON 编码仍按原合同复制，响应/事件没有扩大共享生命周期。
- 旧 BenchmarkCacheConversion 的夹具在两版都因缺少 system_instruction_hoist 失败，不能作为本轮性能回归；替代完整有效链路用 BenchmarkRequestMemoryPipeline。

## 回收、取消与剩余热点

分阶段存活堆、重复 HTTP 和取消测量分别保留在结果 JSON 的 `supplementary`。分阶段 retention 模式主动 GC，只用于定位保留，不混入正式耗时。四并发 2 MiB 在转换/编码中取消各 10 批，只把模型短字段留到末尾，检查短字段没有拖住正文；这不是长时间真实客户端流测试。

- cancellation-baseline/conversion：10 批后存活堆依次为 2.748、2.750、2.752、2.754、2.757、2.758、2.759、2.762、2.763、2.768 MiB。

- cancellation-baseline/encoding：10 批后存活堆依次为 2.770、2.772、2.772、2.774、2.776、2.777、2.778、2.780、2.782、2.784 MiB。

- cancellation-baseline：释放正文、仍保留短模型值后存活堆 0.759 MiB。

- cancellation-optimized/conversion：10 批后存活堆依次为 2.707、2.714、2.715、2.717、2.718、2.720、2.721、2.722、2.723、2.725 MiB。

- cancellation-optimized/encoding：10 批后存活堆依次为 2.726、2.728、2.728、2.730、2.731、2.733、2.735、2.737、2.738、2.740 MiB。

- cancellation-optimized：释放正文、仍保留短模型值后存活堆 0.714 MiB。

独立网关进程连续运行 5 批 ×（JSON、SSE）× 4 并发、2 MiB、媒体外置，共 40 次完整请求，上游均每次只命中一次。排空并 GC 后的存活堆依次为 2.968、3.002、3.005、3.012、3.018、3.024、3.025、3.029、3.032、3.043 MiB。取消探针两版同样有几十 KiB 的小幅增长，尚不能据此证明长期运行的所有对象都不增长；本次证据支持的是没有持续保留每次 2 MiB 正文或媒体的现象，短字段独立化已由存储归属测试同时验证。

新增的真实本地 HTTP 取消测量使用 2 MiB、4 并发、5 批、媒体外置。客户端在收到实际 SSE 事件后分别取消，再等请求/队列排空；全部原始峰值、回收值和上游命中数保存在 `stream-cancellation-*` 记录。它验证的是合成流中的取消，不替代真实供应商的长期流式会话。

- stream-cancellation-baseline：五批取消后存活堆 2.897、2.907、2.910、2.914、2.918 MiB。

- stream-cancellation-optimized：五批取消后存活堆 2.892、2.896、2.900、2.909、2.914 MiB。

独立的 2 MiB CPU profile 中，`jsonStringEnd` 和 `typedMeter.scanRaw` 是主要热点；容器输出缓冲构造是分配热点，`encodeValueContainer` 累积覆盖约 59% 的采样分配。CPU 样本总量只有约 370 ms，包含校验、运行时及测试准备，只用于定位方向，不能把百分比当成精确阶段耗时，更不能当成堆峰值构成。后续仍可研究资源扫描复用和多层容器输出缓冲，但本轮没有为此删除检查或继续扩展共享范围。
