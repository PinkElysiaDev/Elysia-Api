两个原故障由真实网关到模拟 Gemini 上游验证：`stream_options` 不进入 Gemini 请求，客户端 usage 偏好生效；带签名回复按真实上游契约检查，再由策略保存／投影。覆盖并行工具、签名晚到、Anthropic 签名分片和重复快照，真正超出模型工具权限仍被拒绝。

真实客户端验证：

- Claude Code **2.1.293**：实际发起流式请求，执行隔离目录中的只读 Read 工具，再次调用时回传认证载体，模拟上游收到原签名。
- OpenAI Node SDK **7.30.1**：普通和流式工具第二轮均恢复原签名；普通回复携带载体，流式场景主动仅保留标准字段，凭稳定会话匹配加密副本。
- HTTP 恢复回归：工具第一轮后关闭数据库、重建协议注册表并重新监听，再提交不含载体的第二轮；`content:null` 不再使工具的位置变化导致失配。

Claude 验证采用 `--bare --restricted`、短系统提示词、仅 Read 工具、关闭提示缓存／thinking，并显式配置 metadata／output_config 的兼容省略规则。测试未使用真实供应商凭据，不代表所有 Claude Code 默认配置或任意模型都已兼容。SDK 的解析结果须投影回请求字段，不能把 `parsed_arguments` 等 SDK 内部属性当成供应商请求参数。

## 剩余发布门槛

远端原故障的脱敏结构重放和供应商重试尚未执行，不能标记远端故障已关闭。完整客户端配置、历史压缩、真实供应商签名约束与长期会话仍需独立验收。

本轮行为链集成于 HTTP 普通和流式生成；不宣称自定义异步任务、WebSocket 会话及任意 Agent 工作流已经具备相同转换语义。请求固定数据库策略／绑定快照；整个注册表与所有运行时消费者统一代数发布的旧计划仍未整体重构，修订不匹配会拒绝调用。

Gemini `thoughtSignature` 作为完整字段处理，Anthropic `signature_delta` 按分片累积。不根据字符串外观猜测其他供应商的分片模式，不恢复被合并、修改或无法精确关联的历史节点。严格模式拒绝无法保留的对象，兼容模式给出诊断。

当前仓库仍有既有启动迁移流程。本轮修复了重启时预置 ID 循环改名，并接入新增表的版本化迁移，但没有完成此前计划中的全部历史库迁移、实例锁、日志分批迁移等改造。

产物位于 `dist/standalone/`，`conversion-build-manifest.json` 记录六个平台与校验值。`/health` 的提交号仍显示源码基线；区分本次未提交构建须使用该产物清单，不能只看提交号。
