# 四协议转换修复与验收记录（dev.25）

本次基于 `ce52956`，保留工作区已有 dev.24 修改，编译器语义版本为 `2.0.0-dev.25`。修复目标是正确的协议行为；不为旧错误输出增加特殊放行，不以历史测试通过代替协议正确性。用户定义、草稿、绑定及历史修订属于配置数据，与保留错误执行逻辑不是同一回事。

## 根因和实现

上游正常响应曾因附带服务档位、指纹或空 logprobs 被视作未知跨协议扩展；同时目标编码只生成了正文，没有完整构造客户端外壳。对象工具结果又在编码器中隐式转成字符串，验证器比较的仍是原对象。三类问题叠加，造成“修掉一个字段，下一层又报错”。

现在正常附加字段进入 `ResponseMetadata`，保存所属响应／节点、来源编解码模块、路径和值。JSON 和 SSE 使用同一已知字段表；字段类型必须符合声明。未知扩展仍受原有边界约束，不进行“一律删除不支持字段”。

主要修改：

- `response_metadata`：明确映射、空值规范化或有诊断的兼容省略。严格模式拒绝实际损失。Chat↔Responses 公共 URL 引用和 logprobs 保留内容归属；choice 元数据写回该 choice，不再写到响应顶层或覆盖其他附加字段。
- `history-response-metadata`：相同动作也处理下一轮历史。新增并行工具验收发现，Responses 的空 annotations 回传到其他上游仍会阻断第二轮，因此请求阶段也使用同一字段投影。
- `response_shape`：区分同轮多个输出项和多个候选回答；保留工具调用 ID。Chat 合并文本的边界／交错损失有诊断，严格模式拒绝。JSON 重排 URL 引用位置；SSE 按文本项维护有界区段，处理 UTF-16 偏移和重复快照。跨越不连续交错区段的引用明确拒绝，不能错误扩大引用范围。
- `response_envelope`：一次生成并复用响应身份和创建时间；补齐 Chat created、Responses 项目身份、状态、annotations 和事件引用字段。预览／验证注入固定值，避免证据随时间随机变化。
- `tool_result_text`：在语义阶段将对象工具结果序列化为 JSON 文本，保留大整数和调用关联；编码器不再偷偷做同样转换。此转换改变载荷类型，不称作无损；严格模式拒绝。原有面向 Gemini 的具名对象包装继续独立配置。
- `system_instruction_hoist`：Anthropic／Gemini 目标按顺序上提 system/developer。中段作用域、developer 层级变化属于有损兼容；严格模式拒绝。缓存／资源关联不能顺带删除。
- 最终格式校验：请求、JSON、SSE 在映射和线格式处理之后检查。独立目标模块解码器配合事件回放检查流式关联，用户自定义解码映射不能掩盖错误输出。请求尾部再检查工具关联，防止 after 映射制造孤立结果。合法未知原生扩展继续允许。

原始上游用量仍用于内部计量。占位数、客户端投影和元数据省略不会回写供应商观测用量；续传载体也不冒充供应商签名。流式候选上下文在每个事件刷新恢复结果，避免签名晚到时使用过期的可恢复状态。

## 配置与升级

新增动作接入现有 schema 和转换策略页，没有新建策略存储或管理页面。按实际方向模块启用默认规则；旧自定义协议直接使用修复后的模块，完全手写目标编码器不按名称猜测行为。规则沿用已有覆盖、禁用、严格模式和只读预览。

dev.25 和更新后的样例哈希使旧证据重新验证。更新了曾省略必填字段的内置样例和模拟上游，保留原业务断言，没有批量翻转失败预期。移除了本轮一度加入的 Responses 空 annotations 线格式比较豁免，错误输出不能靠比较器过关。合法的原生完整帧仍可原样转发；不完整原生帧由最终校验拒绝。

真实旧库验收发现，旧自定义 Responses 的生成事件样例还缺少 annotations 和项目 status。升级只针对没有 after 映射的内置 Responses 编码器，修正已确定的遗漏；完整验证通过后，在现有事务内创建新修订、激活并刷新绑定。原修订和操作员草稿不覆盖，不按名称改写手写映射。原生回放样例仍断言其原始字节，最终对外发送则必须独立通过正确格式校验。这是修复错误样例，不是放宽运行时协议或比较规则。

## 本地验收设计

`backend/server/gateway_audit_test.go` 和 `gateway_audit_tools_test.go` 使用实际四个预置及 HTTP 网关连接模拟上游，覆盖：

| 场景 | 方向及传输 | 主要断言 |
|---|---|---|
| 普通文本 | 16 方向 × JSON/SSE | 必填外壳、正文、结束事件、无错误 trailer |
| 单函数工具两轮 | 16 方向 × JSON/SSE | 完整首轮回复作为历史，调用 ID 和对象中大整数保留 |
| 正文与并行同名工具两轮 | 16 方向 × JSON/SSE | 两个不同调用 ID；工具参数分片逆序到达；两个工具结果保持关联；完整历史可回传 |

协议层附加回归覆盖：元数据类型、空值／非空值、严格拒绝、未知引用保护、多 choice 归属、URL 引用与 logprobs JSON/SSE 往返、合并文本后的偏移、重复快照，以及最终线格式孤立增量拒绝。既有签名隔离、晚到签名、重启恢复、用量落库和未知厂商扩展测试继续保留。

SDK 验收脚本 `scripts/sdk-audit/replay.mjs` 读取网关捕获的原始输出，不修补测试字节。固定依赖：OpenAI 7.31.0、Anthropic 0.132.1、Google GenAI 2.28.0、Vercel OpenAI 4.0.91、Vercel Anthropic 4.0.78 和 2.0.33。完整消费流，Vercel 路径断言没有隐藏 error 且存在 finish；原生 SDK 检查响应／事件无错误并含生成内容。当前矩阵回放共 320 项通过。

真实后端 Playwright 共 28 项通过，覆盖转换动作表单、预览、严格边界、草稿与并发冲突，以及四预置新库启动和模型发现。新库启动不算升级验收。

升级另外由旧 HEAD 二进制创建真实数据库，再以当前二进制启动；检查自定义修订、草稿和绑定，并连续十次重启检查证据等数量稳定。旧二进制编译器版本为 dev.23；没有把新建空库称作历史升级。

工程修复包括根 workspace lockfile、保持 `npm ci`、按实际 JSON 编码计算无效 UTF-8 字节数。Go 1.25.0／1.26.5／1.27.0 的相关计量测试通过；映射重建的 fuzz 使用语义比较，原生载荷保真仍单独检查。已运行定向 fuzz 15 秒、464565 次执行，没有失败；保留既有反例。

## 明确边界

- 上述 SDK 实验是本地捕获回放，不是用户实际 Cherry Studio 的端到端验收，也不是供应商签名接受性测试。
- 真实渠道、实际客户端版本与脱敏原始结构尚未取得；不能关闭用户原环境故障。交付最多标记“本地修复已验证，原环境待确认”。
- 文件／非 URL 引用、Gemini grounding、非空上下文管理状态、特殊媒体和服务端工具的跨协议能力按具体映射判断，不由普通文本矩阵推导。
- 未实现完整 Responses 历史数据库。非空上一轮引用、截断要求、未知生成参数仍明确拒绝；store 降级不删除上下文约束。
- 某些旧 Anthropic SDK 只采用首帧输入用量。网关可提供合法流，不能保证这些客户端后来更新展示值，也不把客户端占位数写成真实计费。
- 网关成功表示已生成通过检查的下游输出。没有客户端回执时，不能断言客户端界面已成功消费。
